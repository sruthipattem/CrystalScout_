# CrystalScout

CrystalScout is a local research prototype for screening lithium-containing crystal structures. It uses the selected project approach: Extra Trees regression predicts continuous `log10` ionic conductivity in S/cm using 139 composition and structure features. Eligible Materials Project candidates can then be ranked by prediction.

## What is included

- `frontend/`: the indigo and lavender login, dashboard, CIF upload, Materials Project lookup, candidate ranking, model information, and history pages.
- `backend/`: the FastAPI login and screening API, SQLite history, model feature builder, and a script that recreates the model from OBELiX.
- The original user database and model weights are not bundled. The app creates a fresh local account database, and the model is generated by the training step below.

## Run it on Windows

Use Python 3.11 for the materials-science packages. Open PowerShell in this `CrystalScout` folder and run:

```powershell
cd backend
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe train_model.py
```

The training script downloads the official OBELiX train and test CSV files from the public dataset repository if they are not already in `backend/data/obelix/`. It removes the 37 censored conductivity labels (`<1E-10`), computes the 132 Magpie composition features plus seven structure features, trains Extra Trees with the notebook settings, reports held-out and formula-grouped cross-validation metrics, and saves the fitted model under `backend/models/`.

In the same PowerShell window, configure the Materials Project API key for live lookups and candidate ranking. Obtain a key from your Materials Project account; keep it private and do not put it in frontend code. Production is the default and requires a genuine `CRYSTALSCOUT_SECRET_KEY` of at least 32 characters. For local development only, explicitly set `CRYSTALSCOUT_ENV` to `development`; if no secret is supplied, the documented development-only fallback is used. Placeholder secrets are rejected.

```powershell
$env:MP_API_KEY = "paste-your-key-here"
$env:CRYSTALSCOUT_ENV = "development"
$rng = [Security.Cryptography.RandomNumberGenerator]::Create()
$secretBytes = New-Object byte[] 32
$rng.GetBytes($secretBytes)
$env:CRYSTALSCOUT_SECRET_KEY = [Convert]::ToBase64String($secretBytes)
$rng.Dispose()
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

Keep that backend window open. Open a second PowerShell window in the project folder and start the frontend:

```powershell
cd frontend
py -3.11 -m http.server 5500
```

Then visit `http://127.0.0.1:5500`. Create a new account in this copy of the app, since the existing project database was not copied. The backend creates a new `crystalscout.db` file when it starts.

## Screening workflow

1. Register and log in. Your login token is used for protected API calls.
2. Train the model once using `train_model.py`.
3. For a single prediction, upload a lithium-containing CIF file, or enter a Materials Project ID that meets the project filters.
4. Open **Candidate ranking** to fetch lithium-containing Materials Project records, apply the project filters, and rank the survivors. This live search needs `MP_API_KEY` and can take a few minutes.
5. Review saved predictions in **Screening history**.

The current Materials Project filters follow the notebook and project overview: band gap at least 0.5 eV and energy above hull at most 0.10 eV/atom. The filter does not add a transition-metal exclusion. The Materials Project candidate search is live; CIF uploads are parsed locally by the backend.

## How to read a prediction

The model was trained on experimental OBELiX conductivity labels, whose laboratory conditions and reported values can vary. On the notebook's held-out test set, the reported MAE is 1.17 log10 units, roughly a factor of 15 in conductivity. The system therefore presents predictions as ranking estimates. They are not measured conductivities, uncertainty intervals, or proof that a material will work in a battery. DFT-MD or experimental validation remains future work.

## Data and model references

- OBELiX dataset and its CC BY 4.0 license: <https://github.com/NRC-Mila/OBELiX>
- Materials Project API: <https://materialsproject.org/api>
- Base paper: Sendek et al., *Machine Learning-Assisted Discovery of Solid Li-Ion Conducting Materials*, Chemistry of Materials 31, 342–352 (2019), DOI: 10.1021/acs.chemmater.8b03272.

The notebook also explored Random Forest and a seven-feature baseline. This project selects the 139-feature Extra Trees model and evaluates the official held-out split separately from grouped five-fold cross-validation by reduced chemical formula.


## Important local setup notes
- Model predictions are unavailable until `train_model.py` finishes successfully.
- Materials Project ID lookups and live candidate ranking are unavailable without `MP_API_KEY`; CIF predictions only need the trained local model.
- The default environment is production, where `CRYSTALSCOUT_SECRET_KEY` must be a genuine value of at least 32 characters. `CRYSTALSCOUT_ENV=development` must be selected explicitly to enable the local-only fallback when no secret is set; never use development mode or that fallback in production. The `.env.example` file defaults to production and its placeholder is rejected until replaced.
- This is a local prototype, not a production deployment. Keep the API bound to `127.0.0.1` while using the development server.

### Windows blocks PyArrow

The model pipeline reads CSV files and does not need PyArrow. If pandas fails while importing `pyarrow.compute` or Windows blocks `_compute.cp311-win_amd64.pyd`, remove the optional PyArrow package from this virtual environment, then retry the training command:

```powershell
.\.venv\Scripts\python.exe -m pip uninstall -y pyarrow
.\.venv\Scripts\python.exe -c "import pandas as pd; print(pd.__version__)"
.\.venv\Scripts\python.exe train_model.py
```

This does not disable Windows security controls. The `venv` permission error can occur when `.venv` already contains files; avoid rerunning the creation command over that existing environment.

### Windows blocks Pymatgen's compiled extension

If Windows Application Control blocks compiled extensions such as `pymatgen.util.coord_cython` or scikit-learn's `_check_build`, the installed scientific packages cannot run on that device under its current policy. Reinstalling the same wheels may not change that. CrystalScout needs Pymatgen for structure feature generation and scikit-learn for its trained model, so downloading a model file alone is not enough to make local screening work. Use a Python environment where these extensions are allowed, or ask the device administrator to approve the official packages. Do not disable the device's application-control protections to work around this.
